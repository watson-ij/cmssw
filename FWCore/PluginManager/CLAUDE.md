# FWCore/PluginManager

## Purpose
Dynamic shared library loading and plugin factory management. Enables CMSSW's plugin architecture where modules, services, and other components are discovered and loaded at runtime without recompilation of the main executable.

## Key Components

### Plugin Discovery and Loading
- **PluginManager.h** (`interface/PluginManager.h:1`) - Singleton that manages plugin loading
  - Scans plugin cache files (.edmplugincache)
  - Loads shared libraries on demand
  - Thread-safe plugin access
  - Methods: `configure()`, `isAvailable()`, `load()`
- **PluginInfo.h** - Plugin metadata (name, library path)
- **SharedLibrary.h** (`interface/SharedLibrary.h:1`) - Wrapper around dlopen/dlsym
  - Platform-independent shared library loading
  - Symbol resolution

### Plugin Factories
- **PluginFactory.h** (`interface/PluginFactory.h:1`) - Template factory for creating plugins
  - Template: `PluginFactory<R*(Args...)>`
  - Creates instances from type name
  - Thread-safe instance creation
- **PluginFactoryBase.h** - Base class for all factories
- **PluginFactoryManager.h** - Manages multiple factories

### Plugin Registration
- **PluginCapabilities.h** (`interface/PluginCapabilities.h:1`) - Plugin capability registration
- **ModuleDef.h** (`interface/ModuleDef.h:1`) - Module definition macros
  - `DEFINE_FWK_MODULE(type)` - Register a framework module
  - `DEFINE_FWK_SERVICE(type)` - Register a service
  - `DEFINE_FWK_EVENTSETUP_MODULE(type)` - Register EventSetup module
- **PluginFactoryMacros.h** - Generic plugin registration macros
  - `EDM_REGISTER_PLUGINFACTORY(factory, category)`

### Cache Management
- **CacheParser.h** - Parses .edmplugincache files
- **PluginCache.h** - In-memory cache of plugin info
- Cache files generated by `scram build` via `edmPluginRefresh`

### Utilities
- **PluginDescription.h** - Plugin metadata description
- **standard.h** - Standard plugin initialization

## Plugin Architecture

### Plugin Categories
Different plugin factories for different component types:
- **EDM Modules**: Producers, Analyzers, Filters (via `DEFINE_FWK_MODULE`)
- **Services**: Framework services (via `DEFINE_FWK_SERVICE`)
- **EventSetup**: Conditions data producers (via `DEFINE_FWK_EVENTSETUP_MODULE`)
- **Input Sources**: Data sources
- **Output Modules**: Data outputs
- **Custom**: User-defined plugin types

### Plugin Discovery Flow

1. **Build Time** (`scram build`):
   - Compiler sees `DEFINE_FWK_MODULE(MyModule)`
   - Generates static initialization code in .so file
   - `edmPluginRefresh` scans built libraries
   - Writes lib/arch/.edmplugincache with: `plugin_name library_path`

2. **Run Time** (first access):
   - `PluginManager::configure()` reads cache files
   - When module requested: `PluginFactory<edm::EDProducer>::get()->create("MyModule")`
   - PluginManager loads the .so if not already loaded
   - Factory creates instance

### Registration Macros Expansion

```cpp
DEFINE_FWK_MODULE(MyProducer);
```
Expands to:
```cpp
EDM_REGISTER_PLUGINFACTORY(
  edm::WorkerMaker<MyProducer>,
  "MyProducer"
);
```
Which registers the type in the appropriate factory.

## Key Design Patterns

1. **Plugin Factory Pattern**:
   ```cpp
   // Registration (in plugin .cc file)
   DEFINE_FWK_MODULE(MyProducer);

   // Usage (in Framework)
   std::unique_ptr<MyProducer> p =
     PluginFactory<edm::EDProducer*()>::get()->create("MyProducer");
   ```

2. **Lazy Loading**: Libraries loaded only when plugin first requested

3. **Cache-Based Discovery**: Avoids filesystem scanning at runtime

4. **Template-Based Type Safety**: Factories are typed

## Thread Safety
- Plugin loading synchronized via mutexes
- Multiple threads can request same plugin - loaded once
- Factory instance creation thread-safe
- Uses TBB for synchronization

## Cache File Format
```
# lib/arch/.edmplugincache
MyProducer plugin/path/libMyPackageMyModule.so
AnotherProducer plugin/path/libAnotherPackageModule.so
```

## Common Usage Patterns

### Defining a Plugin
```cpp
// In MyProducer.cc
#include "FWCore/Framework/interface/EDProducer.h"
#include "FWCore/PluginManager/interface/ModuleDef.h"

class MyProducer : public edm::EDProducer { /*...*/ };

DEFINE_FWK_MODULE(MyProducer);  // Register plugin
```

### Using a Plugin (Framework internal)
```cpp
auto factory = edm::PluginFactory<edm::EDProducer*()>::get();
std::unique_ptr<edm::EDProducer> module = factory->create("MyProducer");
```

### Custom Plugin Category
```cpp
// Define factory type
typedef edm::PluginFactory<MyInterface*()> MyFactory;

// Register plugin
EDM_REGISTER_PLUGINFACTORY(MyFactory, "MyPlugin");

// Use plugin
auto plugin = MyFactory::get()->create("MyPlugin");
```

## Architecture Notes
- Foundation for CMSSW's modularity
- Enables adding new modules without recompiling framework
- Supports hundreds of plugins per job
- Cache invalidation via `edmPluginRefresh`
- Works across different compilers/platforms

- `edmPluginHelp type` - Show plugin configuration
- Missing plugin error → check cache with `edmPluginRefresh`
- Symbol errors → check library dependencies
